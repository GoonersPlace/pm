# Database

## 1. Technology

SQLite accessed through Qt SQL (`QSqlDatabase`, `QSqlQuery`).

## 2. Source of truth

Versioned SQL files under `backend/migrations/` are the structural database source of truth. This document is explanatory and must remain synchronized with the migrations.

Never edit an already-applied migration to represent a new schema change. After owner approval, create the next numbered migration.

## 3. Initial entities

### `lecturers`

Stores lecturer identity used for scheduling conflicts.

### `rooms`

Stores room name, capacity, optional room type, and active state.

### `student_groups`

Stores groups/cohorts used to detect shared-student conflicts.

### `courses`

Stores course metadata.

### `classes`

Stores schedulable class-session records, including lecturer and room requirements.

### `class_student_groups`

Many-to-many relation between classes and student groups.

### `time_slots`

Stores discrete day/start/end intervals available to Graph Coloring.

### `schedules`

Stores one generated timetable run including algorithm and score summary.

### `schedule_entries`

Maps each class in a generated schedule to one time slot and one room.

## 4. Database rules

- UUID/text IDs are generated by application code for portable MVP simplicity.
- Foreign keys must be enabled with `PRAGMA foreign_keys = ON`.
- Use foreign keys for core relationships.
- Index fields commonly used in joins/conflict checks.
- No soft delete in MVP.
- `created_at`/`updated_at` are used on important mutable entities.
- Do not persist derivable graph edges in MVP unless a later requirement justifies it; the conflict graph can be rebuilt from source data.

## 5. Schema changes

An AI agent must ask before changing tables, columns, data types, foreign keys, unique constraints, or relationships. After approval it must:

1. add a new migration;
2. update this document;
3. update affected API/domain tests;
4. verify migration behavior.
